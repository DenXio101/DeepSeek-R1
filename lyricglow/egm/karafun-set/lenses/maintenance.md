# Lens: Long-term maintenance (structural persona, BRAINSTORM)
App.tsx ≈ 719 lines, ~30 state/ref values, ~20 effects; `source` and `track` are independent and mutated by ≥ 8 handlers with ad-hoc cancellation refs.
1. **Blocker** — No "song" object. → One `SongEntry` type ({track, source, per-song settings, status}) and one `setCurrentSong(entry)` transition — the only path that changes source + track together; existing handlers become thin wrappers. Lands before the queue UI.
2. **Blocker** — Object-URL lifetime is an effect cleanup. → A queue store owns File objects and creates/revokes URLs only on explicit transitions (enqueue, remove, advance); memory cap with a visible message; no revocation in effect cleanups.
3. **Major** — Intro/count-in/next is a hidden state machine. → Explicit reducer with enumerated phases (queued, intro, count-in, playing, finished, grade, advancing) and a legal-transition table + check-model fixture; every phase defines Play/Pause/Restart/Seek/Skip; lives in `src/engine/` next to KaraokeSession.
4. **Major** — `engine.setBeforePlay` is a single slot; an intro delay risks the iOS gesture. → A multi-subscriber / promise-based "play gate" in PlaybackEngine; AudioContext resume stays synchronous in the gesture, delay applied after; YouTube/Listen get no intro (or a documented decoupled one).
5. **Major** — Key shifter = a fourth coupled graph stage; `useVocalLevel` mirrors graph state. → Named ordered stages in AudioGraph (key shifter, vocal reducer, analyser) with a latency contract per stage; feature-detect + clean bypass; shifter behind an interface (`setSemitones`, `latencySeconds`); LGPL licence/size note + fallback story.
6. **Major** — Per-song settings have no home. → Classify every setting per-song (key, tempo, vocals on/off, timing offset) vs per-session (guide level, difficulty, theme, effects); per-song values live on the queue entry read through one selector; App-level `vocalLevel` becomes a default at most.
7. **Major** — Vocals toggle would duplicate the slider path and split the mono rule. → One `vocalLevel` number; toggle = pure function of it (off = 0, on = last non-zero held in the same state); mono verdict from one provider; bar, sheet and hotkeys call the same setter.
8. **Major** — App.tsx would pass 1000 lines. → Extract `useSongQueue` / `src/engine/SongQueue.ts` (KaraokeSession pattern) owning queue, current song, per-song settings, URL lifecycle; pure queue logic with check:model fixtures; App.tsx net-neutral or shorter; a "three songs, advance, key, vocals off" flow test in the repo.
Order: (a) SongEntry + queue store refactor with no visible change, (b) intro + flow state machine, (c) key shifter behind the stage abstraction; vocals toggle rides on the single `vocalLevel`.
